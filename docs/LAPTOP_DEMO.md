# ЛР1 на ноутбуке и передача коллеге

Подготовлен полный приватный комплект: исходники, Git bundle, текущие образы
Docker и согласованный снимок шести volumes. Ноутбук: Windows, 16 ГБ RAM,
Docker Desktop, около 100 ГБ свободного места. Используются Linux-контейнеры.
Для Docker желательно оставить около 8 ГиБ RAM. Настройки Docker автоматически
не меняются; перед вузом нужно реально открыть стенд на ноутбуке дома.

## Передача по локальной сети

Скопировать **всю** папку `lab1-demo-*` с сетевого диска на локальный диск
ноутбука. Нельзя переносить только ZIP исходников: данные и Docker-образы
лежат отдельно. Этот же каталог можно передать коллеге через внешний диск
или закрытую ссылку в облаке; формат восстановления не меняется.

Комплект включает `.env` и локальную конфигурацию Garage. Передавать его
только доверенному участнику проекта; не выкладывать публично и не добавлять
в Git. Публичный репозиторий содержит исходники и отчётные артефакты.

На notebook должны помещаться архивы, образы и развёрнутые данные одновременно.
Указанные 100 ГБ — ориентир для этого снимка; размер конкретного комплекта
указан в `manifest.json`. Не начинать с диска, на котором осталось 10–20 ГБ.

## Запуск перед выездом

1. Запустить Docker Desktop и дождаться готовности Linux Engine.
2. Скопировать комплект локально. Открыть `START.cmd` или выполнить:

   ```powershell
   .\START.cmd C:\ETL_demo
   ```

3. Каталог назначения должен быть **новым**. Скрипт не перезаписывает чужой
   проект и восстанавливает данные только в новые уникальные volumes.
4. Дождаться SHA/CRC-проверок, загрузки образов, извлечения и сравнения всех
   шести файловых систем, проверки PG/Mongo/S3 и готовности Airflow.
5. Открыть [Airflow](http://127.0.0.1:8080). Пользователь `admin`, пароль —
   локальное `AIRFLOW_ADMIN_PASSWORD` в `C:\ETL_demo\.env`.

Переносимый Windows Python включён и проверен отдельно. Git необязателен для
показа: при его наличии восстановится репозиторий, иначе распакуются исходники.
`repository.bundle` позволяет позже клонировать Git без интернета.
На машине с собственным Python можно запустить `restore_portable.py` вручную.

Восстановленная очередь остаётся paused, четыре DAG — тоже paused. Автоматически
собирать сайт с двух компьютеров комплект не начинает. Снимок данных относится
к моменту холодной копии; основной ПК затем может продолжить свой проход.

Если 8080 уже занят другим приложением, сначала освободить его или явно
адаптировать локальный Compose. Скрипт не завершает чужие процессы.
Docker-образы загружаются из архива, `up` использует `--pull never --no-build`.

## Повторный запуск без восстановления

После успешной установки путь к override записан в
`exports/portable-launch.json`. Он нужен: в нём привязка к **восстановленным**
volumes и точным локальным image ID. Использовать сохранённую команду:

```powershell
Set-Location C:\ETL_demo
$demo = Get-Content -Raw exports/portable-launch.json | ConvertFrom-Json
docker compose -f compose.yaml -f $demo.override up -d --no-build --pull never
```

Для остановки — те же два `-f`, затем `stop`. Не использовать `down -v`.
Если набор лежит на внешнем/сетевом диске, не перемещать override после установки
либо скопировать его рядом и изменить сохранённый путь осознанно.

GitHub рендерит Mermaid. Для офлайн-показа схем уже сохранены PNG/SVG рядом
с примером ODS; таблицы, JSON и рисунки сравнения также открываются локально.

Для живой демонстрации при доступном интернете использовать отдельную маленькую
игру через `start-game`, а не возобновлять все 500 игр. Перед этим явно снять
паузу четырёх DAG. Команды и общий limiter — [TEAM_HANDOFF.md](TEAM_HANDOFF.md).

## Для коллеги

Полный комплект подходит для чтения текущих данных и подготовки анализа/отчёта.
Исходники — обычный Git; изменения следует коммитить и передавать через ветки.
Данные в этот Git не входят. Независимый свежий проход должен иметь свой
collection ID, а одновременный сбор с двух ПК не имеет общего файлового limiter:
его нужно заранее согласовать. Переносимый архив не публикует сервисы в интернет.

Готовый комплект на сетевом диске проверен:
`\\Keenetic-7278\toshiba ext\ETL_practice\lab1-demo-20261030T175946Z`.
В нём 116 обработанных игр, 934 836 run ID и 269 010 player ID. Для показа Airflow,
трёх ODS и истории этого достаточно. Повторно переносить гигабайты баз
ради нового отчёта не требуется.

GitHub обновляет исходники, Markdown, CSV, PNG/SVG. В нём **нет** volumes,
staging, `.env` и Garage-ключей. Если стенд на ноутбуке ещё не восстановлен,
одного `git clone` недостаточно: сначала нужен приватный комплект и `START.cmd`.

В уже восстановленном проекте с Git:

```powershell
Set-Location C:\ETL_demo
git status --short
git remote set-url origin https://github.com/UrranQx/Big-Data-Storage-and-Management.git
git pull --ff-only origin main
```

`set-url` нужен, потому что после клонирования из `repository.bundle` origin
может указывать на локальный bundle. При локальных изменениях сначала их
сохранить; не использовать reset/clean ради обновления. Git не меняет базы,
содержимое `.env` или `exports/portable-launch.json`. Обновление текущего
отчёта не требует пересборки Docker-образов и нового восстановления volumes.

Если Git не установлен, скачать ZIP веткиmain из GitHub в отдельную папку.
Из него достаточно скопировать `reports/lab1/`, `docs/` и корневые Markdown-файлы
в восстановленный проект. В частности, обновляются `README.md`, `AGENTS.md`
и `docs/HANDOFF.md`, чтобы указание о ручной остановке тоже дошло до ноутбука.
Локальные `.env`, `infra/garage.local.toml`,
`exports/` и данные при таком обновлении не заменяются.

После обновления открыть [итоговый REPORT](../reports/lab1/REPORT.md),
[сценарий защиты](../reports/lab1/DEMO.md) и новые графики из
`reports/lab1/comparison_20261030/analytics/figures/`.
Сделать это дома с интернетом; затем материалы доступны офлайн.
Для нового ограниченного сетевого ETL на переносимой копии предусмотрена
отдельная подготовка host-disk watcher с правильным Compose override в DEMO.

На ПК сейчас 135 цепочек, во входе новых замеров 128, в переносимой копии 116.
Это три датированных среза. Для переноса именно всех 135 цепочек понадобилась
бы новая согласованная копия БД; GitHub её не заменяет. Для текущей защиты
выбран существующий проверенный снимок 116 игр и свежие отчётные материалы.
