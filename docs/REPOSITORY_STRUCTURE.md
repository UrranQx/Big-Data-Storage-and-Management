# Структура репозитория на три лабораторные

Статус 2026-10-16: реализуется этап малого e2e по `LAB1_PLAN.md`.
Рабочие файлы: `compose.yaml`, `infra/`, `pyproject.toml`, `uv.lock`,
`src/speedrun_etl/{jsonutil,ods,source,storage,collect,workflow,cli}.py`,
`dags/ods/{games_metadata,runs,players}.py`, `sql/{ods,control}.sql`, `tests/`.
Состояние выполнения — `reports/lab1/REPORT.md`. Ниже исходное дерево-план;
DDS/marts остаются будущими этапами без развёрнутых сервисов.

Корневые документы оставлены на прежних местах: сохраняются ссылки и история
обсуждения. `src`, `dags`, `infra`, `sql`, `tests` сейчас содержат только
пояснения; подкаталоги и рабочие файлы создаются по мере необходимости.
Дерево — ориентир, а не требование создать каждый подкаталог или по классу
на каждую сущность. Для ЛР1 допустимы несколько простых модулей без разделения
на все показанные подпакеты. Папки ЛР2–ЛР3 не требуют заглушек и рабочего кода.

Принципы: один проект и общая Compose-конфигурация с дополнением по лабораторным,
общий пакет логики вместо копий клиента по DAG; никаких отдельных приложений
для каждой лабораторной. Рабочие DAG не импортируют архив. Зависимости слоёв
ODS → DDS → витрины добавляются на соответствующем этапе. Superset и
OpenMetadata разворачиваются в ЛР3, а не заранее. Пользовательский сайт,
Twitch/YouTube и ML не входят в обязательный объём ни одной лабораторной.

Данные, секреты, логи, volumes и большие локальные резервные копии не попадают
в Git и Docker build context. Маленькие обезличенные/синтетические фикстуры
будущих тестов должны храниться отдельно от `data/`.
