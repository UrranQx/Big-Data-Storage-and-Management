# Minecraft Java: разница совпала с архивной категорией

| Область | Verified |
|---|---:|
| Основной датасет публичных лидербордов v2 | 29 373 |
| Архивная Combined Any% Glitchless в общем списке v1 | 764 |
| Сумма | **30 137** |
| stats.totalRunsFG до/после и при повторной проверке | **30 137** |

Вся разница 764 численно совпадает с архивной категорией `xd14pv8d`.
Архивные раны существуют: нулевой лидерборд v2 не означает отсутствия
исторических данных. Это сверка публичных API; внутренний SQL `/stats` недоступен.

## Доказательства

Общий v1 `/runs?game=j1npme6p&status=verified&orderby=category&direction=desc`
возвращает архивные записи, хотя категории нет в списке категорий v1.
Точный блок независимо ограничен четырьмя запросами `max=1`:

| Offset | Категория |
|---:|---|
| 83 | All Advancements Co-op |
| 84 | Combined Any% Glitchless |
| 847 | Combined Any% Glitchless |
| 848 | Any% Glitchless (Demo) |

Страницы между границами содержат только Combined Any% Glitchless:
`847 - 84 + 1 = 764`. Исходные ответы с URL/timestamps — в `raw/`;
границы — `exact_archive_boundaries.json`, строки страниц —
`category_order_probes.json`. Свежий лидерборд этой категории в v2
вернул `pagination.count=0`: `final_check/raw/`.

Сортировка v1 только по категории имеет нестабильный порядок равных ключей:
между страницами встречаются повторы ID. Поэтому 764 — независимо проверенный
размер блока, а не сумма уникальных ID наивной пагинации. Перекрывающиеся окна
и стабильные разделы по проверяющим восстановили **745 уникальных ID**.
Перечисление частичное: остальные 19 ID не восстановлены. Все 745 verified,
full-game, с игроками; ни одного нет в основном наборе. Сохранены в
`combined_verified_v1.json`.

Пять карточек v2 проверены индивидуально: `y8vgw8dz`, `m303n1qm`,
`zxq76k8m`, `y2v0x36z`, `y9e314rz`. Все имеют `orphaned=true`, непустой
`playerIds`, `category.archived=true`. Свидетельства:
`archived_sample_cards.json`, `archive_verification.json`.
Orphaned не обязательно означает отсутствие игрока. Конкретное внутреннее
условие присвоения флага не установлено; остальные карточки не проверялись.
Контрольный активный ран `yd47e0jy` имеет активную категорию и не помечен
orphaned: `archive_board_control.json`.

## Что это за записи

Доступные правила переменной Splits и комментарии ранов показывают, что
Combined суммирует подтверждённые PB игрока по разным диапазонам версий
Minecraft. Например, Legacy суммирует Pre 1.9, 1.9–1.15 и 1.16+.
Категория обновлялась ботом. Это агрегаты нескольких отдельных результатов,
а не один непрерывный забег. Правила сохранены в карточках v2 в
`archived_sample_cards.json`; ссылки на составляющие раны — в комментариях v1.

## Исправление прежнего вывода

[znk937lz](https://www.speedrun.com/mc/runs/znk937lz) в Any% действительно
имеет verified и `players=[]` в v1, `orphaned=true`, `issues=["no players"]`
в v2. Полная Any% v1 содержит 435 ID, v2 — 434; единственное отличие — этот ID.

Но его наличие в v1 не доказывает учёт в `/stats`. Прежнее вычитание одного
из разницы и формулировка «763 неизвестных» были преждевременными.
**764 архивных записи уже совпадают со всей разницей.** Участие отдельных ID
в агрегате сайта не раскрывается API; SQL-логику мы ему не приписываем.
Доказательства отдельного orphaned: `any_missing.json`.

Счётчики восьми небольших активных категорий проверены по конечным страницам
v1: все совпали с v2, кроме Any% (+1 указанный orphaned).
Крупная Any% Glitchless полностью в v1 не перечислялась.

## Решение для ETL

Основные таблицы ранов не изменены: сохраняется принятая политика публичных
лидербордов v2 и исключения orphaned. Архивные свидетельства хранятся отдельно.
Метаданные включают архивные категории, но их пустые списки не гарантируют
получение исторических ранов. Для `/stats` сравнивать явно определённые области:
активные лидерборды, архивные агрегаты, orphaned и статусы.

Итог: `report.json`. Воспроизведение границ и карточек:
`verify_minecraft_archive_block.py`, финальная сверка:
`finalize_minecraft_audit.py` в корне проекта. Лимит 20 запросов/мин,
агенты не использовались.
