# Перенос секретов и состояния ЛР3 на другой ПК

Инструкция для переноса существующего стенда. Сам перенос в этом сеансе не
выполнялся. Код берётся из ветки `lab3`; секреты и данные Git не переносит.

## Что передать приватно

| Объект | Куда положить на новом ПК |
|---|---|
| Исходный `.env` целиком | В корень клонированного проекта, с тем же именем `.env` |
| `data/lab3/keys/private_key.der` | По тому же относительному пути |
| `data/lab3/keys/public_key.der` | Рядом с приватным ключом; это одна согласованная пара |

Передайте эти файлы в зашифрованном архиве либо на зашифрованном носителе.
Пароль архива передайте отдельно. Доступ должен быть только у владельца и
коллеги, которому передаётся стенд. Не помещайте секреты в Git, сообщения,
скриншоты, публичные ссылки или параметры командной строки.

Сохраните существующие значения, особенно `SUPERSET_SECRET_KEY` и
`OPENMETADATA_FERNET_KEY`: они связаны с расшифровкой сохранённых секретов в
служебных БД. Произвольная замена ключа не является переносом; для смены нужна
отдельная процедура ротации. Назначение ключей описано в документации
[Superset](https://superset.apache.org/admin-docs/6.1.0/configuration/configuring-superset/)
и [OpenMetadata](https://docs.open-metadata.org/v1.11.x/deployment/oss-security).

Пароли пользователей PostgreSQL должны совпадать с восстановленными ролями.
Сохраните также `AIRFLOW_JWT_SECRET`, пароли входа и RSA-пару OpenMetadata.
`infra/configure_lab3.py` и `infra/lab3_databases.py` создают отсутствующие
значения/ключи; их запуск вместо копирования исходных файлов не восстанавливает
старые секреты. `.env.example` содержит только заглушки.

## Данные переносятся отдельно

Для продолжения того же стенда нужны четыре текущих volume из `compose.yaml`:

- `postgres-data`: PostgreSQL с БД `speedrun_ods`, `speedrun_control`, `airflow`,
  `superset`, `openmetadata` и ролями;
- `etl-state`: checkpoints, ручная пауза, состояние очереди и локальная
  аутентификация Airflow;
- `airflow-logs`: журналы прошлых запусков;
- `lab3-search`: поисковый индекс OpenMetadata.

Фактические имена имеют префикс проекта `speedrun-lab1_`. Для холодной копии
сначала штатно остановите весь Compose-стенд, затем экспортируйте volumes
согласованным комплектом. Не копируйте работающий каталог PostgreSQL как обычные
файлы. Сохраните исходный комплект до проверки восстановления. `down -v` удаляет
данные и для этой процедуры не нужен.

Старый комплект [POSTGRES_ONLY.md](POSTGRES_ONLY.md) переносит ODS/control,
но не всё состояние Airflow/Superset/OpenMetadata. Историческая инструкция
[LAPTOP_DEMO.md](LAPTOP_DEMO.md) относится к прежнему составу сервисов.
Альтернатива полному переносу — восстановить ODS/control и заново построить
аналитический стенд по [DEMO ЛР3](../reports/lab3/DEMO.md); это не сохранит
историю задач и ручные настройки прежних интерфейсов.

## Проверка на новом ПК

До запуска проверьте наличие файлов, не выводя их содержимое:

```powershell
Test-Path .env
Test-Path data/lab3/keys/private_key.der
Test-Path data/lab3/keys/public_key.der
git check-ignore .env data/lab3/keys/private_key.der data/lab3/keys/public_key.der
docker compose --profile lab3 config --quiet
```

После восстановления используйте те же имена проекта/volumes и закреплённые
версии образов. Запустите PostgreSQL и интерфейсы по DEMO. Перед запуском
планировщика подтвердите паузу `games_metadata`, `runs`, `wr_history`, `players`
и отсутствие незавершённых запусков сбора. Сам перенос не разрешает продолжать
старую очередь.

Проверьте `docker compose ps`, вход в Airflow (:8080), Superset (:8088),
OpenMetadata (:8585), наличие трёх дашбордов и lineage, а также чтение витрин.
В текущем срезе ODS — 981599 версий ранов, 280600 версий игроков, 541 manifest;
актуальная публикация и ожидаемые объёмы указаны в [HANDOFF.md](HANDOFF.md).
Сравните эти значения и снимки с исходным ПК до удаления временного комплекта.
