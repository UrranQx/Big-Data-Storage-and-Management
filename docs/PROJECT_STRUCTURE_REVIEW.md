# Обзор структуры проекта и кандидаты на упрощение

Дата: 11 ноября 2026 года.

В проекте **654 файла под Git** на момент обзора. Основная сложность — сочетание действующего ETL, прежней реализации ODS, одноразовых инструментов и большого архива доказательств.

Рабочая цепочка сейчас такая:

`batch → Airflow: games_metadata → runs → wr_history → players → PostgreSQL / MongoDB / Garage`

Ниже — карта файлов и кандидаты на упрощение. Исходники и зависимости проверены статически; сбор, контейнеры и тесты при подготовке обзора не запускались. Исходники не менялись. Для многочисленных результатов экспериментов назначение описано по семействам файлов; это не индивидуальная проверка содержимого каждого JSON. Пути приведены относительно корня репозитория.

## 2. Рабочий Python-пакет

Все перечисленные файлы находятся в `src/speedrun_etl/`.

| Файл | Что выполняет |
|---|---|
| `__init__.py` | Объявляет пакет; импорт не запускает сбор. |

| `cli.py` | Ручной старт, status, evidence, replay и history через CLI/API Airflow. |
| `repair.py` | Дополняет выбранные неполные разделы с сохранением базового снимка и проверкой receipts. |
| `audit_entity_ods.py` | Сверяет локальный пакет с журналом ответов и checkpoints; диагностирует покрытие. |
| `inspect_player_lists.py` | Исследует повторения и изменения встроенных профилей в сохранённых ответах. |
| `forecast.py` | Оценивает ресурсы полного сбора по результатам пилота. |
| `benchmark.py` | Сравнивает загрузку, чтение и размеры трёх ODS на подтверждённых пакетах. |
| `experiment_inputs.py` | Проверяет замороженные входы эксперимента и их происхождение. |

| `analytics_benchmark.py` | Сравнивает аналитические конвейеры: связи, ранги, материализации и обновления; сверяет результаты с SQLite-эталоном. |
| `analytics_sizes.py` | Измеряет размеры входов и результатов аналитического опыта вне таймеров операций. |
| `plot_storage_comparison.py` | Агрегирует CSV обычного сравнения, создаёт таблицы и графики. |
| `plot_analytics_benchmark.py` | Проверяет результаты аналитического опыта, создаёт статистику, CSV и графики. |

| `ods.py` | Прежний формат пакетов: payloads, responses, observations, manifests и восстановление ответа. Часть функций ещё нужна рабочему коду. |
| `storage.py` | Прежние загрузчики и общие подключения PG/Mongo/S3. **Общие подключения активно используются текущей реализацией.** |
| `repack.py` | Не выбранный grouped-history прототип: переупаковывает прежние пакеты с проверкой обратимости. |
| `queue_driver.py` | Прежний top-5 драйвер с фиксированным сроком 16 октября. Запуск через `__main__` отключён. |
| `fresh_cycle.py` | Одноразовая последовательность Half-Life → каталог → Minecraft с фиксированными ID от 16 октября. |

## 9. Рекомендуемый порядок и проверки

Сначала убрать отключённый драйвер и одноразовый цикл, затем отделить общие подключения и fixtures, после этого выводить прежний ODS-код. Разделение больших benchmark-модулей выполнять отдельно, сохраняя воспроизводимость опубликованных результатов.

Для проверки такой очистки важны существующие сценарии: v2/v3, replay, история A→B→A, восстановление JSON, pause/resume, нулевой source HTTP при опытах и чтение одинаковых данных из трёх ODS. Отчётные CSV/JSON, raw evidence, backup и рабочие volumes кандидатами на автоматическое удаление не являются.

Раздел 7 выполнен в описанном выше объёме. Раздел 8 остаётся рекомендациями
для отдельной работы; его большие модули и тесты здесь не перерабатывались.
