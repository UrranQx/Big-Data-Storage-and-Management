# 7. Какие раны разбирать после сдвига WR

[К карте идей](../../ANALYTICS_IDEAS.md)

## Задача

Собрать для выбранного события несколько сопоставимых прохождений, по которым раннер может изучить новый уровень результатов.

## Что показать

1. Прежний WR.
2. Первый ран, который его улучшил в выбранном зачёте.
3. Последующие раны других игроков, которые тоже превзошли прежнюю границу.
4. Даты, размеры улучшений, данные о таймере, платформе и правилах и ссылки на доступные записи.

На графике по дате выполнения показать ступени WR и результаты нескольких раннеров. Можно выделить долю игроков, ставших быстрее прежней границы, дни до повторения достижения и изменение распределения времён. Устойчивость сдвига проверяется на нескольких участниках и с учётом изменения объёма публикаций. Для плотных рядов можно сравнить простые окна и метод обнаружения точек разладки. [Работа о PELT](https://arxiv.org/abs/1101.1438)

## Данные

История должна покрывать отрезки по обе стороны события. По временам видно, что изменились результаты. Конкретный скип, баг или стратегия подписываются по датированному разбору, правилам или записи прохождения. Игроков, пересёкших порог раньше предполагаемого сдвига, можно проверить отдельно для уточнения даты.
